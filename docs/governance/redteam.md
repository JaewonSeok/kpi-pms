# 레드팀 운영 규약

| 항목 | 값 |
|---|---|
| 표준 근거 | AI Native SDLC Requirements §6.2, §2.4 |
| 수립일 | 2026-09-18 |
| 해소 대상 | 1회차 자가 진단 §6.2 "레드팀 반론 검토 기록 없음" |

---

## 1. 표준이 요구하는 것

> 항상 레드팀(Red Team)을 운영하여 반대의견을 검토해야 한다.
> 의무 적용 지점: **기획 확정 전, 설계 확정 전, 실서비스 전환 전,
> 주요 아키텍처·보안 결정 시.**
> 레드팀은 **작성 세션과 독립된 AI 세션**으로 수행하고, 반론과 검토 결과를
> **기록**한다.
> 본 절이 다루는 반대의견은 레드팀의 반론과 **인간이 제기한 반론을 모두
> 포함**한다(필수). 제기된 반론은 **채택 여부와 무관하게 기록**한다.

핵심 3가지:

1. **4개 트리거** — 하나라도 빠지면 미준수
2. **독립 세션** — 작성한 세션이 스스로 검토하는 것은 레드팀이 아니다
3. **기록** — 채택되지 않은 반론도 남긴다

---

## 2. 트리거별 기록 위치

새 디렉터리를 만들지 않고 기존 산출물에 반론 절을 붙인다. 결정이 기록되는
곳에 그 결정에 대한 반론이 함께 있어야 찾을 수 있다.

| 트리거 | 기록 위치 | 형식 |
|---|---|---|
| 기획 확정 전 | ADR | "레드팀 반론" 절 |
| 설계 확정 전 | ADR | "레드팀 반론" 절 |
| 주요 아키텍처·보안 결정 | ADR | "레드팀 반론" 절 |
| 실서비스 전환 전 | `docs/operations/release-readiness.md` | Red team checklist 절 |

### ADR 반론 절 형식

```markdown
## 레드팀 반론

| # | 반론 | 제기 | 채택 | 처리 |
|---|---|---|---|---|
| 1 | <반론 내용> | AI 독립세션 / 인간 | 채택 / 기각 | <반영 내용 또는 기각 사유> |
```

★ **기각한 반론도 반드시 남긴다.** 채택된 것만 적으면 검토가 있었다는
증거가 되지 않는다.

## 3. kpi-pms 의 독립성 구조

kpi-pms 는 3자 구조로 운용된다.

| 역할 | 담당 |
|---|---|
| 아키텍트 (설계·판정) | 웹 Claude 세션 |
| 실행자 (구현) | 로컬 Claude Code 세션 |
| 승인자 | 재원 |

아키텍트와 실행자는 **서로 다른 세션이며 컨텍스트를 공유하지 않는다.**
실행자는 아키텍트의 지시를 기계적으로 따르지 않고, 전제가 틀렸을 때 멈추고
보고한다.

### 이 구조가 실제로 작동한 기록 (2026-09 세션)

| # | 아키텍트 지시 | 실행자 반론 | 결과 |
|---|---|---|---|
| 1 | `.gitleaksignore` 지문 기반 억제 | 줄 번호 변동에 깨진다 | 룰 기반으로 변경 |
| 2 | 테스트 FAIL 31건으로 판정 | `-r register-path-aliases.ts` 누락. 7건은 조사 오류 | 63/24 로 재분류 |
| 3 | `envKey` 필드 오탐 | 실제로는 `key` 필드 | 정규식 정정 |
| 4 | `--soft` 리셋으로 정리 | 인덱스에 이전 커밋 잔존 | `restore --staged` 추가 |
| 5 | `origin/main` 에서 분기 | 대상 파일이 main 에 없음 (미푸시) | cherry-pick 으로 전환 |
| 6 | amend 후 태그가 따라온다 | amend 는 해시를 바꾼다 | 재태깅 |

★ 6건 모두 **아키텍트의 오류를 실행자가 잡은 것**이다. 반대 방향(실행자
산출물의 검토)은 아키텍트가 상시 수행한다.

### ★ 이 구조로 덮이지 않는 것

**아키텍트와 실행자가 둘 다 동의한 결정은 검토되지 않는다.**

두 세션 모두 같은 계열의 모델이며, 같은 맹점을 공유할 수 있다. 실제로
2026-09 세션에서 다음이 둘 다 통과했다.

- `#302` 가 도입한 `Session` 교차 타입 회귀 — 양쪽 모두 `user` 를 required
  로 만드는 것의 위험을 인지하지 못했다. CI 미등록 테스트 때문에 이틀 뒤
  발견
- `#303` 의 감사 귀속 코드가 무검증 상태였다는 것 — 음성 대조를 수행하고
  나서야 드러났다

따라서 3자 구조는 **레드팀의 부분 대체일 뿐 완전한 대체가 아니다.**
가능하면 다른 계열 모델의 독립 세션을 쓴다.

## 4. 도구 — change-simulation

전사 공유 스킬 `change-simulation-v2.1.0` 을 **실서비스 전환 전** 트리거에
사용한다.

| 항목 | 내용 |
|---|---|
| 호출 | `/change-simulation` (Claude Code) |
| 범위 | 작업트리 변경 → 사용자 지정 범위 → 최근 커밋 2개 순 |
| 판정 태도 | 코드·문서의 계약을 기계적으로 대조. 설명을 호의적으로 보완하지 않음 |
| 산출 | 후보 질문 + 채택/기각 사유, 코드 경로, 실행 명령과 실제 출력, 판정 기준 |
| 제약 | "프로젝트 전체" 같은 광범위 요청은 거부. 좁은 변경 범위 대상 |

★ 이 스킬은 **최근 좁은 변경**을 대상으로 한다. 기획·설계 확정 전 트리거는
성격이 달라 이 도구로 대체되지 않는다. 그 트리거들은 ADR 반론 절로 처리한다.

### ★ 선행 조건 — 스킬 접근

현재 이 스킬은 `rnd-ai-sdlc-main` 저장소에만 있고, 그 저장소는 **`C:\dev`
클론에만 실물이 존재**한다. Desktop 작업 클론에서는 호출할 수 없다.

**미조치.** 스킬을 사용 가능한 위치로 옮기기 전까지 실서비스 전환 전
트리거는 3자 구조의 상호 검토로 대체한다.

## 5. 운영 규칙

- 반론은 **채택 여부와 무관하게 기록**한다. 기각 사유를 함께 적는다
- **인간이 제기한 반론도 기록 대상**이다. AI 반론만 적으면 §6.2 미준수다
- 반론 제기 자체는 평가에 불리하게 작용하지 않는다(§6.2 명시)
- 레드팀 세션에는 **결정의 근거가 된 요약이 아니라 원본**을 준다. 요약은
  작성 세션의 해석이 섞여 있어 같은 맹점을 물려준다

---

## 6. 미결

- **스킬 접근 경로** — `change-simulation-v2.1.0` 이 작업 클론에서 호출
  불가 (4절)
- **ADR 소급 적용 안 함** — ADR 0001 은 반론 절 없이 작성됐다. 소급
  작성하지 않고 0002 부터 적용한다
- **다른 계열 모델 확보** — 3자 구조가 같은 맹점을 공유하는 문제(3절)의
  해소 수단이 없다
- **`release-readiness.md` Red team 절 신설** — 이 문서와 함께 추가
