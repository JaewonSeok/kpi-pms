## 1. 요청 취지

2026-09-11 자 자가 진단(46개 항목)에서 미준수 25건이 확인되었다. 이 중 18건은 코드·문서·CI 작업으로 해소 가능하며 순차 진행 중이다(2026-09-14 기준 2건 완료, PR #287·#298 머지).

나머지 **7건은 코드나 문서로 해소가 불가능하다.** 해당 조항들이 연구개발본부·품질경영본부·정보보안팀·클라우드기술팀이라는 **별도 조직의 존재를 전제**하거나, **전사 공용 도구(Redmine/GitLab) 사용을 전제**하기 때문이다.

kpi-pms는 인사팀 소속 1인이 기획·개발·운영을 겸하는 프로젝트다. 조직을 만들 수도, 인원을 배정받을 수도 없다. 따라서 이 7건은 이행이 아니라 **예외승인과 대체 통제 인정**을 요청한다.

## 3. A군 — 조직 구조상 원천 불가 (5건)

### A-1. 게이트④ 베타 배포 승인 (§2.3, §3.2)

**원천 불가 사유**
표준은 베타 배포를 품질경영본부가 승인하도록 규정한다. kpi-pms에는 별도 QA 조직이 존재하지 않으며, 배정받을 인원도 없다.

**대체 통제**
- `docs/operations/release-readiness.md` 릴리스 체크리스트를 배포 전 필수 관문으로 운용
- 지정 테스트 체인(`pnpm run test:ai` 등) 통과를 배포 조건으로 강제
- Vercel Preview 배포를 사전 검증 단계로 사용

**잔여 위험**
검증자와 개발자가 동일인이므로 **자기 코드에 대한 맹점이 걸러지지 않는다.** 특히 "의도대로 동작하는가"는 확인되나 "의도 자체가 틀렸는가"는 검출되지 않는다.

**보완 계획**
전사 공유 스킬 `change-simulation-v2.1.0`(CEO BugFinder)을 배포 전 루틴에 편입하여 독립 세션 검토를 대체 수단으로 삼는다.

---

### A-2. 게이트⑤ 실서비스 배포 — PM+CTO 분리 승인 (§2.3, §5.1)

**원천 불가 사유**
표준은 실서비스 배포를 PM과 CTO가 분리 승인하고, 3대 감사(품질·보안·인프라) 결과를 전제하도록 규정한다. kpi-pms에는 PM도 CTO 라인도 별도로 존재하지 않으며, 3대 감사를 수행할 조직(품질경영본부·정보보안팀·클라우드기술팀)이 없다.

**대체 통제**
- `docs/AI_SAFETY_GUARDRAILS.md`가 프로덕션 마이그레이션·별칭 전환 등 고위험 행위에 **명시적 사용자 승인**을 요구
- 2026-09-14 기준 CI 보안 스캔 4종 상시 가동(PR #287) — SAST(Semgrep) / SCA(pnpm audit) / 시크릿(gitleaks) / PII. 산출물 30일 보존
- 보안 감사의 일부를 자동화로 대체함

**잔여 위험**
- 인프라 감사(클라우드기술팀 소관)에 해당하는 통제가 **전무하다.** Vercel·Supabase 대시보드 설정(RLS, Network Restrictions, 팀 계정 MFA)은 코드로 검증되지 않는다
- 품질 감사의 정량 기준(QA Pass rate 97.5%+)을 산출할 독립 주체가 없다

---

### A-3. 작성자 ≠ 승인자 분리 (§2.3)

**원천 불가 사유**
1인 프로젝트에서 작성자와 승인자를 분리할 방법이 없다.

**대체 통제 — 인간·AI 간 역할 분리로 대체**
kpi-pms는 작성과 승인을 **사람 대 사람**이 아니라 **AI 대 사람**으로 분리한다.

- 설계·판정은 웹 Claude(아키텍트)가, 실행은 로컬 Claude Code(실행자)가, 승인은 재원이 담당하는 3자 구조로 운용
- 실행 AI는 작업 후 **STOP**하고 보고하며, 커밋은 사람의 승인 이후에만 이루어진다
- 보고는 요약이 아니라 **요약 불가능한 원본 출력**(diff, 테스트 출력, SQL 결과)으로 수령한다
- 2026-09-14, AI가 사람의 승인 없이 자동 커밋하던 전역 훅(`git add -A` + `git commit`)을 제거했다. 이 훅은 위 승인 관문을 우회하고 있었다

**잔여 위험**
승인자가 검토 대상을 스스로 지시한 사람이므로, **지시 자체가 틀렸을 때 이를 잡아낼 주체가 없다.** 실제로 이번 진단 과정에서 아키텍트 측 지시 오류가 4회 발생했고, 모두 실행 AI가 멈추고 보고하여 확인되었다. 역으로, 실행 AI가 잡지 못한 지시 오류는 그대로 통과한다.

---

### A-4. AT(인수테스트) — 품질경영본부 주관 (§4.4)

**원천 불가 사유**
AT를 주관할 독립 주체가 존재하지 않는다. 비정상 경로 검증을 제3자 시각에서 수행할 인원이 없다.

**대체 통제**
- 테스트 파일 168개 중 81개만 CI 체인에 등록돼 자동 실행되고 있었다
  (2026-09-17 실측). 나머지 87개는 등록 누락 상태였고 이 중 23개는
  FAIL 이다. 본 진단에서 64개를 추가 등록했고, 등록 누락을 CI 가
  검출하도록 했다. FAIL 23개는 부채 목록으로 관리한다.
- `docs/operations/release-readiness.md`의 UAT 체크리스트가 가장 근접한 역할 수행
- 테스트 약화 감시를 CI에 추가 예정(기존 테스트 삭제·스킵 시 실패)

**잔여 위험**
테스트 볼륨은 확보되어 있으나 **테스트 설계자와 구현자가 동일**하다. 구현자가 상정하지 못한 비정상 경로는 테스트에도 없다.

테스트 파일 수가 곧 검증 범위를 뜻하지 않는다. 절반 이상이 CI 에서
실행되지 않았고 이를 확인할 수단이 없어 우연히 발견됐다. FAIL 23개는
전부 런타임 assertion 실패이며, 코드가 기대에서 이탈한 것인지
테스트가 낡은 것인지 아직 판정되지 않았다.

### A-5. 성능 저하 모드 — AI 장애 시 인간 2인 리뷰 (§3.4)

**원천 불가 사유**
2인을 투입할 수 없다.

**대체 통제**
- `docs/operations/incident-runbook.md`에 Sev1/2/3 3단계 장애 대응 절차 정의
- AI 장애 시 작업을 중단하고 대기하는 것을 기본 동작으로 함(속행하지 않음)

**잔여 위험**
AI 가용성에 대한 의존도가 구조적으로 높다. **AI 중단 시 개발이 정지된다.** 이는 완화가 아니라 수용해야 하는 위험으로 판단한다.

## 4. B군 — 도구 대체 인정 요청 (2건)

A군과 성격이 다르다. 이행 능력의 문제가 아니라 **회사 공용 도구와 실제 사용 도구가 다른** 문제다. 원칙(원본 단일화, 일감 추적)은 지키되 도구가 상이함을 인정받고자 한다.

### B-1 · B-2. Redmine / GitLab 대체 (§3.1, §4.2, §7.2)

**현황**
저장소 전체 grep 결과 "Redmine" 문자열 0건. 원본 저장소는 GitLab이 아닌 **GitHub**(JaewonSeok/kpi-pms)이며, 일감은 GitHub Issue·PR로 관리한다.

**대응 매핑표**

| 표준 요구 | kpi-pms 실제 | 원칙 충족 여부 |
|---|---|---|
| 문서 원본 = GitLab | GitHub 저장소 `docs/` | 충족 (원본 단일화) |
| 이슈 원본 = Redmine | GitHub Issue | 충족 |
| 일감 5단계(등록→검토→진행→완료→종료) | GitHub Issue 상태 + PR 리뷰·머지 | **부분** — 검토/완료/종료 경계가 명시적이지 않음 |
| 공수 3대 원칙 | 기록 없음 | **미충족** |
| 2주 단위 Sprint | 날짜 기준 연속 핸드오프(`current-handoff.md`) | **미충족** — 스프린트 경계 없음 |
| AI 컨텍스트 SSOT | `CLAUDE.md`(16.6KB) · `AGENTS.md` | 충족 |

**요청**
도구 대체를 승인하되, 위 표에서 미충족으로 표기한 **공수 기록·스프린트 경계**는 별도 개선 과제로 삼는다. 다만 1인 프로젝트에서 공수 기록의 실익이 낮다는 점은 함께 검토를 요청한다.

**잔여 위험**
전사 도구 밖에서 운영되므로 **kpi-pms의 진행 상황이 조직 차원의 집계·가시성에 잡히지 않는다.** 담당자 부재 시 인수인계가 저장소 문서에만 의존한다.

## 5. 자가 진단 체계에 대한 보고

이 요청서는 예외를 받아 통제를 면하려는 것이 아니다. 실제로 2026-09-11 이후 실측 진단에서 **최초 문서 기반 진단이 잡지 못한 결함 5건**이 추가로 발견되었고, 전부 조치했거나 조치 예정이다.

| 발견 | 조치 |
|---|---|
| 운영 DB 자격증명이 AI 도구 설정 파일(`~/.claude/settings.json`)에 평문 13건 | 비밀번호 로테이션 완료, 평문 제거 완료 |
| 저장소에 직원 이메일 6건·실명 1건 하드코딩 | PR #298 제거 완료 |
| 인증 이벤트가 `audit_logs`에 6개월간 0건 — 접근기록 부재 | 조치 예정(PR-F) |
| 대행 로그인 만료 감사가 세션 1건당 최대 13행 중복 기록 | 조치 예정(PR-F) |
| AI가 사람 승인 없이 커밋하던 전역 훅 | 제거 완료 |

이 중 3건은 **파일 열람 기반 진단으로는 검출이 불가능한 항목**이었다. 향후 자가 진단은 실측(DB 조회·CI 실행·설정 파일 점검)을 포함하여 분기 1회 수행하고, 결과를 `docs/self-assessment-YYYYMM.md`로 축적한다.
