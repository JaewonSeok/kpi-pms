## 3. Act — 개선 판단

### 3-1. 유지할 것

**AI 작업의 STOP-보고-승인 구조.** 이번 달 아키텍트 측 지시 오류가 최소 5회
있었고 전부 실행 AI 가 멈추고 보고해서 확인됐다 —
`-r register-path-aliases.ts` 누락으로 인한 FAIL 오분류 7건, `envKey` 대
`key` 필드 오인, `--soft` 리셋 시 인덱스 잔존, PR #287 미머지 상태, round1
파일 부재. 요약이 아니라 원본 출력으로 보고받는 규칙이 이를 가능하게 했다.

**음성 대조.** 통제 장치를 만들 때 고의로 위반 사례를 넣어 검출되는지
확인하는 방법. 이번 달 이것으로 두 건의 무검증 상태를 확인했다(#303 의
감사 귀속, `org-kpi-team-ai-workspace` 테스트).

### 3-2. 바꿀 것

**핸드오프 문서를 롤링 덮어쓰기에서 누적 기록으로.** `current-handoff.md` 가
6월 29일에서 멈춘 것은 갱신을 잊었기 때문이 아니라, 덮어쓰는 형식이라
갱신하지 않으면 그냥 옛 상태가 남기 때문이다. PDCA 월간 기록이 이 역할을
대체한다.

**심각도 표기 통일.** 4갈래 파편화를 방치하면 결함 등급 매핑 자체가
불가능하다. 표준 4등급 정의를 확인하고 하나로 수렴시킨다.

### 3-3. 이번 달 실패에서 배운 것

**#302 → #304 회귀.** 타입을 좁힐 때 `Session['user']` 를 required 로 만들어
plain `Session` 호출부가 전부 깨졌다. `tsc --noEmit` 은 통과했고 `ts-node` 만
깨졌는데, 그 차이를 잡을 테스트가 CI 체인 밖에 있어 2일간 방치됐다.

교훈 둘:
- 타입 변경은 "무엇을 추가하는가" 보다 "무엇을 필수로 만드는가" 가 위험하다
- 전체 프로그램 타입 검사(`tsc --noEmit`)와 진입점별 검사(`ts-node`)는 다르다.
  전자 통과가 후자를 보증하지 않는다
