## 1. 경로 규약

표준은 *"릴리즈별로 구분되도록 저장소 경로 규약을 프로젝트 시작 시 정하고,
게이트⑤ 증적 링크가 그 경로를 가리키게 한다"* 고 규정한다. 경로 형식 자체는
고정하지 않으므로 kpi-pms 는 다음으로 정한다.

```
docs/audit/
├── README.md              ← 이 문서. 규약과 범위
└── <릴리스 태그>/
    ├── quality.md         ← 품질 감사
    ├── security.md        ← 보안 검사
    └── infra.md           ← 인프라 감사
```

- 디렉터리명은 **Git 태그와 정확히 일치**시킨다 (`v0.1.0.0`)
- 릴리스 태그가 없으면 감사 문서를 만들지 않는다. **릴리스 식별이 선행 조건**이다
- 게이트⑤(실서비스 배포) 증적 링크는 `docs/audit/<태그>/` 를 가리킨다
- 세 파일은 감사를 수행하지 않았더라도 **골격으로 존재**시킨다. 없는 것과
  수행하지 않은 것을 구분하기 위함이다

### 현재 릴리스

| 태그 | 커밋 | 비고 |
|---|---|---|
| `v0.1.0.0` | `4c2b490` | 베이스라인. 이 태그 이전 이력은 릴리스로 구분되지 않는다 |

## 3. ★ kpi-pms 의 구조적 제약

**세 감사 모두 별도 조직이 주관하도록 설계돼 있고, kpi-pms 에는 그 조직이 없다.**

특히 보안 검사 가이드 §1 은 다음을 명시한다.

- 최종 판정 주체는 **정보보안팀이며 AI 가 아니다**
- **의뢰형 점검**(웹 취약점 점검 OWASP Top10 / AI 모의해킹 / 소스코드 정적분석
  신청)은 정보보안팀 요청이 필요하며 **AI·개발팀이 자체 수행할 수 없다**

따라서 이 디렉터리의 문서는 **감사 결과 보고서가 아니라 1차 검사 결과**다.
최종 판정란은 비워두고 담당 조직 제출용으로 작성한다.

이는 [예외승인 요청서](../governance/exception-request-20260914.md) A-2(게이트⑤
3대 감사 전제)와 같은 구조적 제약이며, 이 규약으로 해소되지 않는다.

### 작성 원칙

- **근거 없이 '적합' 판정 금지.** 설정 캡처·API 응답·스캔 리포트·코드 인용 중
  하나가 반드시 있어야 한다
- 수행하지 않은 항목은 **'미수행' 으로 표기**한다. 수행한 것처럼 쓰지 않는다
- 쓰지 않는 기능은 **'해당없음' + 사유**
- 확인 불가 항목은 추측하지 말고 **담당자 질문으로 이관**한다
- 판정 등급 체계는 [결함 심각도 체계](../governance/defect-severity.md) 2-1 참조
