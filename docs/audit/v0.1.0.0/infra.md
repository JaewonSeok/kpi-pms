## 1. 미수행 사유

인프라감사는 **클라우드기술팀이 주관**하며 kpi-pms 에는 해당 조직이 없다.
[예외승인 요청서](../../governance/exception-request-20260914.md) A-2 참조.

★ 2회차 자가 진단에서 **인프라 감사에 해당하는 통제가 전무**함을 확인했다.
Vercel·Supabase 대시보드 설정(RLS, Network Restrictions, 백업 주기, 이중화)은
코드로 검증되지 않으며, 이번 세션에서 확인 시도조차 하지 않았다.

## 3. 플랫폼 구성 (사실 기록)

감사 판정이 아니라 현재 구성의 사실 기록이다.

| 계층 | 플랫폼 | 플랜 |
|---|---|---|
| 애플리케이션 | Vercel | Pro (Custom Domain 은 미활성) |
| 데이터베이스 | Supabase | Pro (`aws-1-ap-northeast-1`) |
| Postgres | 17.6.1.084 | 업그레이드 가능 알림 있음 (17.6.1.166) |

★ 가이드 §6-1 은 **관리형 백엔드 플랫폼(BaaS)과 클라우드 IaaS 의 책임경계**를
구분하도록 규정한다. kpi-pms 는 전면 BaaS 구성이므로 이중화·백업·인증서의
상당 부분이 플랫폼 책임이다. 다만 **어디까지가 플랫폼 책임이고 어디부터가
프로젝트 책임인지 문서화돼 있지 않다.**

## 4. 확인이 필요한 항목

인프라 감사를 수행하려면 대시보드 접근이 필요하며, 아래는 코드로 판정할 수
없다.

| # | 확인 대상 | 위치 |
|---|---|---|
| 3-1 | Supabase 백업 주기·보존 기간, PITR 활성 여부 | Supabase 대시보드 |
| 3-2 | RTO/RPO 목표 정의 존재 여부 | 미정의 |
| 5-1 | 모니터링·알림 구성 | Vercel / Supabase |
| 8-1 | 로그 보존 기간 | Vercel Runtime Logs |
| 9-1 | 배포 산출물 보존 정책 | Vercel |

★ 특히 3-1·3-2 는 **운영 DB 에 전 직원 평가 데이터가 있는 시스템**에서
가장 무거운 항목이다. 이번 세션에서 자격증명 로테이션을 수행했으나, 그
과정에서 백업 상태를 확인하지 않았다.
