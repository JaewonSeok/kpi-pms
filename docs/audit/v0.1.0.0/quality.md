#### 검증 방식 실태 (2026-09-21 조사)

표준 §4 는 *"수치 충족만을 위한 무의미한 테스트를 막기 위해, AI 리뷰로
테스트가 실질 검증을 하는지 함께 확인한다"* 고 요구한다. 그 이행으로
전수 조사를 수행했다.

**판정 기준**: `readFileSync`/`existsSync` 로 `src/` 파일을 읽고
`.includes()`/`.match()` 로 문자열 존재만 확인하는가, 아니면 대상 모듈을
실제로 호출하는가. `require()`·동적 `import()` 경로까지 추적했다.

| 구분 | 파일 수 | 비중 |
|---|---|---|
| 혼합 (텍스트 검사 + 실제 호출) | 79 | — |
| **텍스트 전용** (호출 없음) | **17** | 147 대비 11.56% |
| 그중 CI 등록 | 13 | 147 대비 8.84% |
| 그중 고아 (부채 목록) | 4 | CI 미실행 |

텍스트 전용 17개의 테스트 케이스 합계는 **88건**이다.

**표본 검증 3건** — 대상 소스에서 검사 문자열을 임시 제거하고 실행:

| 파일 | 제거 대상 | 결과 |
|---|---|---|
| `admin-ops-metrics-contract` | `failedJobs24h` | FAIL |
| `korean-copy-hotfix` | `360 다면평가` | FAIL |
| `evaluation-workbench-member-route` | `getEvaluationWorkbenchPageData` | FAIL |

3건 모두 FAIL 했다. **완전한 무검증은 아니다.**

#### ★ 한계 — 이 조사가 답하지 못한 것

**(1) 텍스트 전용은 존재 확인이지 동작 검증이 아니다.**
함수명 변경·삭제, UI 문구 제거는 잡는다. 함수 내부 로직 오류, 잘못된
인자, 기대와 다른 반환값은 잡지 못한다. 표준 §4 의 "실질 검증" 에
미달한다.

**(2) 파일 단위 측정이라 케이스 단위 텍스트 검사를 놓친다.**
`org-kpi-team-ai-workspace.test.ts` 는 이 조사에서 "혼합" 으로 분류되나,
2026-09-16 실측에서 `auditActor` 스프레드를 통째로 제거해도 7/7 PASS
했다. 한 파일이 함수를 호출하면서 특정 검증만 문자열로 때울 수 있으며,
그 경우 이 분류로는 드러나지 않는다.

**케이스 단위 재측정이 필요하다. 미수행.**
